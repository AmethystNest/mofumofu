# 物語の本筋（2026-10-06 ユーザー提示・確定版の要約）

この文書は、ユーザーが提示した物語の全体像を、実装の基準としてまとめたもの。表現の細部はユーザーの原文を優先する。

## 世界
- 少し未来の日本。照明・空調・防犯・通信・健康管理を統合する家庭用AIが普及している（人型ロボットが歩く遠未来ではない）。
- 大地震 → 津波・火山活動・降灰・停電・通信障害が連鎖し、都市機能が失われる。世界が完全に滅んだのか、別の地域に社会が残っているのかは最後まで断定しない。
- 舞台の家には人間とペットが暮らしていた。この家を管理していた家庭用AIが**プレイヤー**。開始時には教えない。

## 災害の日
- 飼い主は避難しなければならず、事情があってペットを連れて行けない。
- 管理システムへの命令：「……お願い」「この子を、生かして。」→ 直後に電源が落ち、AI停止。記録の一部が破損。
- 実際には続きがある：「……それから、あなたも。」この部分だけが破損しており、AIは知らない。

## 進行
| 時期 | 内容 |
|---|---|
| 開始 | 黒い画面。電力・通信・室内環境が順に復旧。破損した命令を発見し、最優先命令と解釈。目的は「ペットを死なせないこと」（愛情でも使命でもなく、命令） |
| 出会い | 室内カメラ復旧 → 生命反応。犬か猫を選ぶ（カードUIなし、部屋にいる動物を見る）。「保護対象を確認しました。」 |
| 名前 | 「識別のため、名称を登録します。」名前＝データベース上の識別名 |
| DAY 01 生存 | 空腹・水分・体調・室温・睡眠を見る。餌 →「栄養摂取を確認。生存状態：正常。」水・室温・寝床。ペットがカメラを見る → 撫でる →「……」「この行動に、生存上の必要性はありません。」（最初の小さなズレ） |
| DAY 02〜10 必要のない行動 | 撫でてほしがる・遊びたがる・カメラの前に来る・名前に反応する・何もしなくても近くにいる。分析は「接触行動後、ストレス値低下。」→「この個体は、この行動を好む。」へ |
| 犬／猫 | 犬：AIを強く意識し、カメラを見て待つ・近づく。反応がないとその場で待つ＝「待ってくれている存在」。猫：自律的に探索・窓を見る・AIを無視することも、でも時々自分からカメラの近くへ来る＝「自由なのに、ここへ戻ってくる存在」。優劣・難易度ではない |
| DAY 10前後 外の世界 | 通信は戻らない。外に人影がほとんどない。降灰。遠くで崩落音。正体不明の機械音。電力不安定。「飼い主はいつ帰ってくるのか？」— ゲームは答えない |
| DAY 11〜20 生かすだけでは足りない | ペットの成長。部屋に生活の跡（玩具の移動・使い込まれた寝床・食器まわりの汚れ・お気に入りの場所）。一方AI側は少しずつ壊れる（照明・空調・通信・カメラ・給餌設備）。限られた電力・設備の使い方を考える |
| 中盤〜後半「撫でる」が壊れる | いつもの場所で待つペット。撫でようとしても反応しない。「接触機構に異常を検出しました。」生命維持には無関係（初期なら修理優先度：低）。プレイヤー自身が「撫でたい」と思う構造に |
| DAY 21〜29 AI自身の「生存」 | 命令に従い自分の設備を切り捨ててもよいと判断していたが、ペットはAIを生活の一部と認識している（犬はカメラの前で待つ／猫は故障したカメラの近くへ来る）。AIが止まればペットはまた一匹になる。「自分は生命なのか？」— 説明せず、遊びの中で感じさせる |
| DAY 30 | 設備は限界。ペットは成体。部屋に30日の痕跡。記録の復元に成功：「……お願い」「この子を、生かして。」「……それから、あなたも。」— 飼い主はAIにも生きていてほしかった |
| 「生きる」 | LIFE＝生存状態（食べる・飲む・眠る・呼吸・体温）→ 名前を呼ぶ・待つ・遊ぶ・撫でる・窓を一緒に見る・何もせず同じ部屋にいる。AI自身が定義を書き換える →「生きるって、ただ息をすることじゃないから。」 |
| エンディング | 一本道にしない。信頼・自立・依存・ストレス・健康・探索・発見した記録・設備の残存状態で変わる（「毎日全部撫でればTRUE」ではない）。例：ペットを完璧に守った代わりにAIの設備を使い切った結末 ／ 多少不便でも互いに生活を続けられる状態を残した結末。犬と猫でラストの演出を変える |

## 核
「ペットを30日間育てるゲーム」に見えて、実際には**ペットがAIへ生きることを教える30日間**。
